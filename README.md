# Nimbus Auth Server

Сервер аккаунтов для Nimbus Launcher. Аккаунт создаётся один раз, и вход работает с любого компьютера, где в лаунчере указан адрес этого сервера.

## Быстрый запуск на своём ПК

```
npm start
```

Сервер слушает `http://127.0.0.1:3000`, данные лежат в `data/db.json`. Подходит для проверки.

При запуске сервер печатает адрес для других ПК в той же сети, например `http://192.168.1.50:3000`. Укажи его в лаунчере на втором ПК — этого достаточно, пока сервер включён. Для доступа через интернет нужен постоянный сервер с https (ниже).

## Как открыть доступ с разных ПК

Нужен постоянный адрес в интернете и **постоянное хранилище**. Если хранилища нет, аккаунты исчезнут после перезапуска сервера.

### Вариант 1. Render (проще всего)

1. Загрузи папку `NimbusAuthServer` в репозиторий GitHub.
2. В Render выбери **New → Blueprint** и подключи репозиторий. Render прочитает `render.yaml`.
3. Blueprint создаёт сервис с диском `/var/data` и переменной `DATA_FILE=/var/data/db.json`.
4. Диск доступен только на платном плане **Starter**. На бесплатном плане база будет теряться при перезапуске.
5. После деплоя получишь адрес вида `https://nimbus-auth.onrender.com`.

### Вариант 2. Railway

1. **New Project → Deploy from GitHub**. Railway сам найдёт `Dockerfile`.
2. Добавь **Volume**, точка монтирования `/data`.
3. Переменные: `DATA_FILE=/data/db.json`, `PORT=8080` (Railway обычно задаёт порт сам).
4. В настройках сервиса включи публичный домен и получи `https://…up.railway.app`.

### Вариант 3. Свой VPS

```
docker build -t nimbus-auth .
docker run -d --name nimbus-auth --restart unless-stopped \
  -p 127.0.0.1:3000:8080 \
  -v /srv/nimbus-auth:/data \
  -e DATA_FILE=/data/db.json \
  nimbus-auth
```

Снаружи поставь HTTPS-прокси, например Caddy:

```
auth.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

Caddy сам получит сертификат. Адрес `https://auth.example.com` и будет адресом сервера.

**HTTPS обязателен:** лаунчер не отправляет пароли на удалённый сервер по http.

## Подключение лаунчера

В лаунчере открой **Настройки → Сервер аккаунтов**, вставь адрес сервера и нажми **Сохранить адрес**. После этого войди заново.

Адрес по умолчанию для сборки задаётся в `NimbusLauncher/resources/server.json`. Переменная `NIMBUS_AUTH_URL` перекрывает и файл, и настройку.

## Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PORT` | `3000` | порт сервера |
| `HOST` | `0.0.0.0` | адрес прослушивания |
| `DATA_FILE` | `data/db.json` | путь к базе аккаунтов и сессий |

## Резервные копии

Копируй `db.json` (на хостинге — файл по пути из `DATA_FILE`). В нём все аккаунты и активные сессии.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/` | страница состояния |
| GET | `/api/health` | проверка работы |
| POST | `/api/register` | `{username, password, repeat}` → токен и пользователь |
| POST | `/api/login` | `{username, password}` → токен и пользователь |
| GET | `/api/me` | заголовок `Authorization: Bearer <токен>` → пользователь |
| POST | `/api/logout` | завершает сессию |

Пароли хранятся как scrypt-хэш. После 8 неверных попыток вход блокируется на 15 минут, регистрация с одного адреса ограничена 10 в час. UUID игрока совпадает с оффлайн-UUID Minecraft для этого ника.

## Сайт и CORS

Сервер отдаёт CORS-заголовки для `GET`, `POST` и `OPTIONS`, поэтому статический сайт `NimbusSite` может обращаться к `/api/login`, `/api/register` и `/api/me` с другого домена. Адрес сервера указывается на странице `account.html` и хранится в браузере.

Для публичного сайта нужен HTTPS: страница на https не сможет обратиться к http-серверу из-за mixed content. Локально можно использовать `http://127.0.0.1:3000`.
